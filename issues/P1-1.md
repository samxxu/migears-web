# P1-1 — A logger registered in the container is still ignored by the framework: …

## Finding / 问题

- EN: A logger registered in the container is still ignored by the framework: its own errors only use the third constructor argument, while the README shows two different ids — `resolve(LoggerInterface::class)` and `set("logger", ...)` — which are not the same channel, so copying the example yields a NotFoundException or a silent no-op.
- 中文: 容器里注册的 logger 仍被框架忽略：框架自身错误只用构造器第 3 参，而 README 展示了两个不同的 id——resolve(LoggerInterface::class) 与 set("logger", ...)——并非同一通路，照抄示例会得到 NotFoundException 或静默无效。
- Where / 位置: `src/MiRest.php:34,60,158,165 vs README:164,180,445,461`
- Verification / 验证: reproduced / 已实证

## Thread

- 2026-09-27 · `reviewer — migears-full-review` · `open` — filed from the round-4 report.
- 2026-09-28 · `owner — migears-web` · `fixed` — **fixed.** The framework now takes its logger from the container only, so the two-id conflict the finding describes cannot recur.
  - `MiRest::handle()` resolves `Psr\Log\LoggerInterface` from the container before dispatch starts; the constructor's third parameter and the private `explicitLogger` field are gone, and with them the three-tier priority (constructor → container → `NullLogger`). A missing or wrong-typed entry now throws on the first request instead of a silent `NullLogger` no-op; silence is an explicit registration, `$rest->set(LoggerInterface::class, fn() => new NullLogger())`.
  - The README no longer presents two ids: both bootstrap examples and the container section use `\Psr\Log\LoggerInterface::class` throughout, plus a new "The framework's own logger" section (EN/ZH) stating the container-only rule.
  - The container path landed in `60e4f7e`; removing the constructor channel and the silent fallback is the 2.1.0 change. Tests: `MiRestTest::testErrorLogging`, `::testUnregisteredLoggerFailsLoudly`, `::testARegisteredNonLoggerEntryFailsLoudly`, `::testNullLoggerSilencesFrameworkErrors`; the obsolete `testExplicitLoggerTakesPriorityOverContainer` and its now-redundant twin `testLoggerRegisteredInContainerIsUsedByFramework` were deleted.
  - 中文: **fixed。** 框架的 logger 现在只从容器取，finding 所说的两个 id 不再可能冲突。`MiRest::handle()` 在分发前从容器解析 `Psr\Log\LoggerInterface`；构造器第 3 参与私有字段 `explicitLogger` 一并删除，三层优先级（构造器 → 容器 → `NullLogger`）随之消失。未注册或类型不对的条目会在第一个请求上抛错，而非静默 `NullLogger` 无效；静默改为显式注册。README 中英 bootstrap 与容器章节统一为 `\Psr\Log\LoggerInterface::class`，并新增「框架自身的 logger」小节。容器通路落在 `60e4f7e`；移除构造器通道与静默兜底是 2.1.0 的改动。
