# P2-2 — `class_exists($className, false)` is treated as proof the target file …

## Finding / 问题

- EN: `class_exists($className, false)` is treated as proof the target file is loaded. When an exact directory and a wildcard directory on the same level generate the same FQCN, the second request skips `require_once` and reuses the class from the other file: `GET /users/user_id` and `GET /users/999` both returned the exact-directory implementation.
- 中文: class_exists($className, false) 被当作「目标文件已加载」的证明。当同层精确目录与通配目录产生同一 FQCN 时，第二个请求会跳过 require_once 并复用另一个文件里的类：GET /users/user_id 与 GET /users/999 都返回了精确目录那份实现。
- Where / 位置: `src/MiRest.php:193-195`
- Verification / 验证: reproduced / 已实证

## Thread

- 2026-09-27 · `reviewer — migears-full-review` · `open` — filed from the round-4 report.
- 2026-09-28 · `owner — migears-web` · `fixed` — **fixed** in `60e4f7e`. `MiRest::loadResourceClass()` no longer treats `class_exists($className, false)` as proof that the located file is loaded: it compares `ReflectionClass::getFileName()` with the located `$filePath` through `realpath()` and throws a `RuntimeException` on a mismatch, so an exact/wildcard FQCN collision is reported instead of silently reusing the other file's implementation. Pinned by `MiRestTest::testExactAndWildcardDirectoriesCannotSilentlyShareAClass` (the second request answers 500).
  - 中文: **fixed**（`60e4f7e`）。`loadResourceClass()` 不再把 `class_exists(..., false)` 当作目标文件已加载的证明：用 `ReflectionClass::getFileName()` 与定位到的 `$filePath` 经 `realpath()` 比对，不一致即抛 `RuntimeException`，精确/通配 FQCN 冲突被报告而非静默复用。由 `MiRestTest::testExactAndWildcardDirectoriesCannotSilentlyShareAClass` 固化（第二个请求返回 500）。
